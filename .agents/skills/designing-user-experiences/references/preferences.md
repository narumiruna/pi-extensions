# Adjustable Interface Preferences

Read this file when the task reaches visual direction or when comparing multiple structurally valid options. These are defaults, not universal usability laws. Explicit product requirements, user evidence, brand rules, accessibility, content needs, and platform conventions take precedence.

| Dimension | Default preference | Adjust when |
| --- | --- | --- |
| Density | Calm and spacious, with enough information and target spacing for efficient scanning and operation | Expert workflows require comparison, monitoring, or high-throughput work; never compress below accessible target and focus requirements |
| Information amount | Show task-critical context; disclose secondary detail | Missing context would force navigation or memory, or dense comparison is the task |
| Containers | Use open grouping and whitespace before cards or bordered panels | A boundary communicates interaction, selection, ownership, or a distinct state |
| Corners | Use restrained, consistent radii | Existing design-system tokens or platform conventions specify otherwise |
| Color | Use a limited functional palette for hierarchy, state, and feedback, with noncolor cues for essential meaning | Brand expression is important and does not compete with meaning, contrast, or appearance adaptation |
| Typography | Use a legible, compatible UI family for operational surfaces; reserve monospaced type for technical values | Editorial or expressive presentation is a product goal, the full script set has been tested, and display type does not weaken scanning or fallback consistency |
| Motion | Use brief, cancellable motion to explain continuity, causality, or state change | Reduced-motion preferences, urgency, performance, repeated use, or discomfort argues for a reduced or static alternative |
| Labels | Prefer concise verb labels and familiar symbols; use text when it is clearer | Space is constrained and the icon is conventional, unambiguous, labeled for assistive technology, and not the only route to a core action |
| Action emphasis | Prefer one primary nondestructive action, with at most one additional prominent action | Evidence shows that multiple peer actions are equally central; never make a destructive action the default |
| Navigation | Keep common paths shallow and preserve orientation | A deeper structure makes a large domain meaningfully easier to understand |
| Decoration | Prefer purposeful visual detail over ornament | Expressive presentation is itself a product goal and does not impair task clarity |

## Preference Resolution

1. Satisfy accessibility, agency, recovery, privacy, and consequential-state visibility.
2. Preserve the primary task, functional completeness, and context.
3. Follow established product and platform conventions.
4. Use evidence about frequency, expertise, inputs, and environment.
5. Apply these defaults only where the earlier constraints leave a genuine design choice.

When deviating from a default, state why the context benefits. When applying a default, describe the concrete layout or interaction choice instead of using style adjectives alone.
