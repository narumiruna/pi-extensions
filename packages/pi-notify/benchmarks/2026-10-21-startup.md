# pi-notify startup measurements

The prebuilt Jiti entry reduces package import work while retaining eager provider validation and the existing lazy notification menu. Root Git installations retain source entrypoints.

## Samples and protocol

The [raw samples](./2026-10-21-startup.json) contain eight isolated startup series and twelve first-use series, including warm-ups, baseline responses, timestamps, summaries and environment metadata. Each series has seven measured processes after one excluded warm-up. Measurements used Pi 1.3.0, Node v26.10.0 and macOS arm64.

Warm mode primes Jiti's filesystem cache; cold mode disables it, not the operating-system cache. Startup uses offline RPC without model requests or user extensions. Values below are milliseconds as median (median absolute deviation, MAD).

| package / warm | 85 (4) | 11 (0) | 245.91 (3.34) | 170.56 (0.50) |
| package / cold | 243 (4) | 131 (2) | 411.37 (7.81) | 296.70 (6.81) |
| source / warm | 81 (1) | 83 (1) | 241.90 (1.07) | 248.70 (2.76) |
| source / cold | 245 (3) | 240 (2) | 408.45 (2.68) | 403.07 (2.10) |

These are standalone loads. Joint-load timings and acceptance evidence are archived in the [historical comparison](https://github.com/narumiruna/pi-extensions/blob/33887af87a12d1640b62cdc3d8f3127b89ebdde2/docs/benchmarks/2026-10-21_inspect-notify-startup.md) and [joint samples](https://github.com/narumiruna/pi-extensions/blob/33887af87a12d1640b62cdc3d8f3127b89ebdde2/docs/benchmarks/2026-10-21_inspect-notify-startup.json) at a fixed commit, not copied into this package's isolated samples. Source entrypoints do not receive the prebuilt package-entry speedup.

### First use

The POSIX-only model-free harness starts its timer after extension loading and `session_start`, and stops it at the first custom menu opening. It loads no real notification destinations or credentials and closes the menu with Ctrl+C. Actual terminal rendering, provider delivery and model execution are not measured.

| Entry / cache | Before | After |
| --- | ---: | ---: |
| package / warm | 23.69 (0.15) | 15.53 (1.75) |
| package / cold | 62.45 (1.41) | 47.11 (5.50) |
| source / warm | 24.24 (0.34) | 24.45 (0.10) |
| source / cold | 61.53 (1.04) | 60.39 (1.94) |
| installed / warm | 41.56 (0.90) | 30.44 (0.51) |
| installed / cold | 283.86 (3.11) | 290.83 (7.15) |

Installed samples used production-only tarball installations. Both baseline and new installations resolved published Kit 0.65.6; workspace measurements used Kit 0.66.0. The much larger installed cold first-use cost includes the external Kit menu runtime and must not be compared directly with the workspace result.

First-use changes remain within the larger of 10% or twice the baseline MAD. These are local measurements, not a performance guarantee; timing thresholds are not deterministic unit-test assertions.

## Reproduction

Run from the repository root after `npm install` and `npm run build`:

```sh
npm run benchmark:extension-startup -- --entry packages/pi-notify --baseline --runs 7 --cache-mode warm
npm run benchmark:extension-startup -- --entry packages/pi-notify --baseline --runs 7 --cache-mode cold
npm --workspace @narumitw/pi-notify run benchmark:first-use -- package
JITI_FS_CACHE=false npm --workspace @narumitw/pi-notify run benchmark:first-use -- source
```

For source startup, append `/src/index.ts` to the startup entry. Repeat first-use commands in separate processes and discard the first sample; select `source` or `package` independently of the cache mode. The [package-owned first-use script](../scripts/benchmark-first-use.mjs) resolves its entry independently of the working directory.

This directory is repository-only and is excluded by the package's published `files` list.

## Package verification and limits

- Generated Jiti tests cover passive factory registration, eager validation, lazy menu imports, cancellation, repeated cleanup, session replacement, failed initialization, command modes, settlement delivery and in-flight aborts.
- Source tests cover all built-in providers, settings and metadata without live provider traffic. The initial focused suite passed 1,809 tests before the five package-owned benchmark tests were added.
- Package/source command-mode, trusted discovery, RPC reload/replacement/shutdown, and installed lazy-menu smokes passed.
- Pack inspection found 32 published files with runtime entries/maps and license; benchmark reports, samples, scripts and tests are excluded.

A direct macOS focused run exposed an existing `/var` versus `/private/var` metadata-fixture mismatch; canonical-temp focused and root runs passed. No provider retry, delivery timing, settings or model-visible behavior changed.

The archived comparison records the shared gates, guides and remaining limitations. Direct interactive terminal smoke and Windows behavior were not newly verified. No package publication, version tag or release workflow was performed.
