# Pi Sync startup loading

Normal startup no longer loads command execution, snapshot processing, or file recovery implementations before they are needed. Pending file transactions still recover before session initialization completes.

## Measurements

Each case uses five separate Pi RPC processes after one warm-up. The agent directory is empty, Pi is offline, and no provider request is made. Warm mode uses the Jiti filesystem cache; cold mode disables it. These results measure an unconfigured startup, not recovery or a configured remote check.

Environment: linux x64, 6.18.33.2-microsoft-standard-WSL2, Node.js v26.11.1.

All values are milliseconds. Arrows show before → after medians. First response includes Pi core startup and the local initialization barrier; it is not pure extension cost. Each series also records a no-extension baseline, whose first-response medians ranged from 175.89 to 194.79 ms in these runs.

Run from the repository root, replacing the entry and cache mode for each case:

```sh
npm --workspace @narumitw/pi-sync run build
npm run benchmark:extension-startup -- --entry ./packages/pi-sync --runs 5 --cache-mode cold --baseline
npm run benchmark:extension-startup -- --entry ./packages/pi-sync/src/index.ts --runs 5 --cache-mode warm --baseline
```

Do not use these host-specific measurements as a test threshold. First command execution and pending recovery still pay the deferred import cost.
