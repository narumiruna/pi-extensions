# pi-inspect startup measurements

The prebuilt Jiti entry reduces package import work. Browser assets remain in a separate `browser-dist` directory; source loading remains supported for production Git installations.

## Samples and protocol

The [raw samples](./2026-10-21-startup.json) contain eight isolated startup series and twelve first-use series, including warm-ups, baseline responses, timestamps, summaries and environment metadata. Each series has seven measured processes after one excluded warm-up. Measurements used Pi 1.3.0, Node v26.10.0 and macOS arm64.

Warm mode primes Jiti's filesystem cache; cold mode disables it, not the operating-system cache. Startup uses offline RPC without model requests or user extensions. Values below are milliseconds as median (median absolute deviation, MAD).

Joint-load timings and acceptance evidence are archived in the [historical comparison](https://github.com/narumiruna/pi-extensions/blob/33887af87a12d1640b62cdc3d8f3127b89ebdde2/docs/benchmarks/2026-10-21_inspect-notify-startup.md) and [joint samples](https://github.com/narumiruna/pi-extensions/blob/33887af87a12d1640b62cdc3d8f3127b89ebdde2/docs/benchmarks/2026-10-21_inspect-notify-startup.json) at a fixed commit, not copied into this package's isolated samples. Source entrypoints do not receive the prebuilt package-entry speedup.

### First use

The POSIX-only model-free harness starts its timer after extension loading and `session_start`. It grants synthetic consent, starts the real loopback server, and stops the timer after successful HTML/JS/CSS reads. Desktop browser launch is suppressed. Human confirmation, browser rendering and model execution are not measured.

| Entry / cache | Before | After |
| --- | ---: | ---: |
| package / warm | 22.31 (0.30) | 19.69 (0.36) |
| package / cold | 25.15 (1.09) | 23.69 (0.10) |
| source / warm | 22.33 (0.54) | 23.37 (0.53) |
| source / cold | 24.24 (0.59) | 24.74 (1.02) |
| installed / warm | 22.44 (0.51) | 19.28 (0.13) |
| installed / cold | 23.87 (0.43) | 23.74 (0.38) |

Installed samples used production-only tarball installations. The original source entry and manifest came from the baseline Git archive; unchanged browser assets were copied into its original output layout before packing. Source and generated viewer paths used real disk assets.

First-use changes remain within the larger of 10% or twice the baseline MAD. These are local measurements, not a performance guarantee; timing thresholds are not deterministic unit-test assertions.

## Reproduction

Run from the repository root after `npm install` and `npm run build`:

```sh
npm run benchmark:extension-startup -- --entry packages/pi-inspect --baseline --runs 7 --cache-mode warm
npm run benchmark:extension-startup -- --entry packages/pi-inspect --baseline --runs 7 --cache-mode cold
npm --workspace @narumitw/pi-inspect run benchmark:first-use -- package
JITI_FS_CACHE=false npm --workspace @narumitw/pi-inspect run benchmark:first-use -- source
```

For source startup, append `/src/index.ts` to the startup entry. Repeat first-use commands in separate processes and discard the first sample; select `source` or `package` independently of the cache mode. The [package-owned first-use script](../scripts/benchmark-first-use.mjs) resolves its entry independently of the working directory.

This directory is repository-only and is excluded by the package's published `files` list.

## Package verification and limits

- Generated Jiti tests cover real HTML/JS/CSS, authenticated snapshots, read-only context capture, command modes, missing-asset retry, replacement and repeated shutdown.
- Browser-builder tests cover isolated imports, deterministic output, stale files, symlink ownership, validation and rename failures, restoration, and build/prepack failure ordering.
- The browser suite passed 134 tests, including a real Pi live session, credential rotation and shutdown.
- Production Git installation with development dependencies omitted built and served assets without runtime output; retained source discovery and RPC reload/replacement/shutdown smokes passed.
- Pack inspection found 68 published files with runtime entry/maps, assets and license; benchmark reports, samples, scripts and tests are excluded.

Browser and runtime publication are separate transactions; either build failure stops build/prepack. Simultaneous writers and crash durability are not supported.

The archived comparison records the shared gates, guides and remaining limitations. Direct interactive terminal smoke and Windows behavior were not newly verified. No package publication, version tag or release workflow was performed.
