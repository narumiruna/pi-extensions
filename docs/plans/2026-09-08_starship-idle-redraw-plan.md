# Fix pi-starship idle redraws

## Goal

Resolve [issue #1237](https://github.com/narumiruna/pi-extensions/issues/1237) by suppressing unchanged periodic footer render requests while preserving data refreshes, time display updates, and lifecycle safety.

Implementation, signed commits, branch push, and a pull request are authorized by the execution request. Publication remains unauthorized.

## Context

`packages/pi-starship/src/pi-starship.ts` requests Git and workspace refreshes every 30 seconds and then unconditionally calls `tui.requestRender()`. `AsyncRefreshController` already compares snapshots before publishing, and the Git, workspace, and GitHub PR publication callbacks request renders. The unconditional timer call bypasses that suppression.

Removing that call alone needs a compatibility check: `src/modules/time.ts` renders `runtime.now` as local `HH:mm`, independent of collector snapshots. `runtimeSnapshot()` also traverses session history for usage and turn counts, so replacing the unconditional render with an unconditional full runtime snapshot calculation would retain avoidable idle work.

The issue's CPU measurements are reported evidence, not a reproduced benchmark. A render request does not by itself prove that every terminal cell is rewritten.

## Non-Goals

- Detect tmux or terminal visibility, add Pi APIs, or suspend background collection.
- Change polling intervals, settings, public commands, dependencies, or runtime-loading architecture.
- Guarantee zero idle CPU or introduce a broad rendering cache or usage-accounting refactor.

## Risks

A collector-only fix can freeze the clock. A naive full-footer comparison can preserve history traversal costs. Reachability must include effective previews and actual output semantics, not only whether the time module is globally enabled. Initial or restarted controllers can legitimately publish even when a later steady-state refresh would compare equal; tests must establish the appropriate baseline.
