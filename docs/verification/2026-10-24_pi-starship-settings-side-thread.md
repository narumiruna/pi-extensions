# pi-starship settings side-thread verification

## Outcome

`/starship` → **Configure with agent…** opens a separate, fullscreen, in-memory configuration agent. It explicitly loads the bundled skill and exposes only `read`, `write`, and `edit`. Agent mutations affect a private draft. Valid changes redraw the footer preview without reload; a reviewed user save creates a named profile before a separate confirmation can apply it to active settings.

## Architecture and semantic audit

The implementation uses the public `Agent` from Pi agent-core, not a default SDK session. `modelRegistry.streamSimple()` retains the parent's request-time authentication, custom providers, header transforms, and supported virtual-model routing without discovering parent extensions or creating a second credential store. The model/thinking selection and ordered tools are captured at flow start. Consecutive normalized request tests preserve the existing system/tool/message prefix. Each new chat is a separate prefix epoch with fixed draft/resource paths and an independent routing session ID.

The owning extension retains all settings policy. Core file-tool operations enforce the draft boundary after native path resolution. Reads use an immutable active-file snapshot or approved package/draft content. Writes and edits accept only the private draft; symlinks, hard links, non-regular files, stale owners, and oversized drafts are rejected. An outer queue orders reads, mutations, and their diagnostics; core mutators retain their own file-path queue. Invalid draft bytes remain available for repair while the last valid preview stays active.

Preview calls only the existing redraw path; it does not restart module collectors or activate draft-enabled commands/network requests. Publication reuses the existing managed History and guarded atomic commit implementation. The application boundary checks disk bytes/identity, loaded revision, draft revision, saved profile bytes/identity, and session ownership. Profile creation reuses `saveAsProfile()` and existing atomic store operations, validates names, and retries invalid or colliding names without overwriting. The profile exists before the apply confirmation. Declining closes the chat without applying; application failure retains the profile. Cancelling naming returns to chat, while hard cancellation and stale ownership during naming close the workflow without creating a profile. Archive/write/apply failures, invalid-original repair, missing-file creation, repeat attempts, conflicts, and cancellation have focused tests.

Lifecycle review covers user cancellation, component disposal, native confirmation, partial initialization, session replacement, reload, and shutdown. The child is aborted and awaited before draft removal. UI subscriptions and abort listeners are removed. Tools remain disabled after a cleanup failure, and draft removal can be retried after permissions recover. Session generation and `sessionManager` ownership prevent stale preview or publication callbacks. Shutdown awaits the registered child cleanup.

The UI uses Pi's public fullscreen overlay, native `CustomEditor`, native user/assistant/tool message components, and Kit review/framing primitives. The transcript grows above a fixed editor/preview dock. Native message backgrounds, Markdown, padding, and inter-question spacing replace flattened role-prefixed text. The body uses Pi's native theme handling; dock chrome uses callback-provided roles. Theme invalidation recreates native components to remove captured colors. Display caches are released on disposal, and disposed or aborted views render no new content. No second TUI or shared-terminal handoff is needed. Native submission already expands paste markers; moving an unsubmitted draft uses `getExpandedText()`. Input-action collisions take precedence over review cancellation. Table-driven tests cover aliases, modifier order, printable input, legacy control collisions, Kitty/modifyOtherKeys packets, invalid bindings, native editing fallbacks, and Escape fallback. Ctrl+C remains hard discard. Display controls are removed before transcript/diagnostic layout; raw agent payloads are unchanged.

## Guides and decisions

Reviewed applicable MUST rules and touched-area checklists in `docs/extension-conventions.md`, `docs/extension-settings.md`, and `docs/readme-conventions.md`. Skill changes follow `create-agent-skills`; child instructions follow the general `prompt-gpt` principles without assuming one provider or model.

The final diff was reviewed for correctness, security, lifecycle safety, compatibility, regressions, and scope. No implementation question or required agent check remains open. There are no accepted exceptions to the required root gates.

The existing TOML settings format, single source forwarder, generated entrypoint, and command routes remain unchanged. The new child runtime stays behind a dynamic command import; generated-import and eager-graph tests cover that boundary. The only added Pi peer is agent-core, with its matching workspace development dependency and lockfile entry. A minor Changeset records the published behavior change.

Intentional UI differences are documented in the package README: the fullscreen view shows recent messages with expanded read-only tool output, full reviews expose the transcript/document, editor actions win cancel-key collisions, Escape is a fallback, and reviews require **Continue**. Cancelling a review discards the temporary draft but retains any previously saved profile; disposal cannot serve as acceptance of a save review. Chat history, automatic compaction/retries, and parent usage accounting are not added.

## Message queue follow-up audit

The side thread uses public `Agent.steer()`, `followUp()`, `continue()`, and queue-clear methods. The child keeps Pi's default one-at-a-time queue modes. User messages are appended at the conversation tail; tests compare normalized request prefixes and ordered tools across steering, tool continuation, and follow-up delivery. No tools, main messages, permissions, or prefix mutations are added.

`SettingsChatEditor` now extends public `CustomEditor` and registers only message follow-up and dequeue actions. Native app-action priority, explicit history overrides, matcher aliases, invalid/disabled bindings, first usable alternatives, legacy/Kitty/modifyOtherKeys packets, and terminal-mode differences have parity tests. The flow still handles hard discard and review cancellation first. Native Editor handles bracketed paste directly while a paste is active, so app shortcuts inside fragmented paste cannot consume its contents. Large-paste follow-ups and queue restoration use expanded text. Message-key defaults remain platform-specific and configurable; no new message shortcut hints are displayed.

Owned queue metadata is removed by exact user-message identity at `message_start`, not by text matching, so identical text in different queues remains distinct. Display copies are sanitized and dimmed above the editor; at most three pending rows are shown, with the total count on its border. Width/height bounds and bottom-aligned preview behavior remain intact. Raw queued model content is unchanged.

The run promise covers actual Agent idle settlement, including awaited `agent_end` listeners. Messages submitted after the loop's final queue poll continue only after settlement. Cancelled or failed runs never auto-continue: undelivered input is restored in steering-then-follow-up order ahead of the expanded unsent editor draft. Submission while cancellation settles retains the input. Hard discard, disposal, session abort, and shutdown clear both queues, abort the run, and await completion before draft removal. Tests cover each cancellation route, duplicate messages, multiple messages per queue, explicit dequeue, error/abort restoration, and late steering/follow-ups with and without cancellation.

The real-CLI smoke holds the first provider response until the PTY observes both queued-message rows, then releases a file-event barrier. It verifies the ordered initial/steering/follow-up messages, tool continuation, and unchanged parent transcript. The fixture pins the configured follow-up key to Ctrl+Q rather than assuming the host's platform default. Watchers and abort listeners are released on completion, abort, and shutdown; no fixed sleeps, external provider calls, or new production background tasks are added.

## Save shortcut and cancellation restoration audit

Ctrl+S opens the existing exact-review, named-profile-save, and independent apply-confirmation flow directly while idle with a valid draft. F2 is the first fallback if Ctrl+S is reserved by Pi's native input, cancellation, history, or registered message actions. If both keys conflict, the shortcut is omitted and the review menu remains available. The dim border label shows only the selected executable key. Candidate legacy, Kitty, and modifyOtherKeys packets are checked through Pi's matcher against effective TUI/application bindings; actual input is checked again before dispatch. Busy, invalid, paste, and key-release states cannot activate a save. Existing editing and queue actions keep priority, and moving a draft preserves expanded paste text. Tests cover aliases/case, modifier order, invalid configured strings, terminal modes, multiple conflicts, and the first usable fallback; real CLI save scenarios use Ctrl+S.

A regression test first reproduced stale draft preview after Ctrl+C through the complete command handler. The outer command's terminal observer aborts the command owner, so the old cleanup guard incorrectly skipped preview clearing. Cleanup now uses the existing session-current predicate, independent of user cancellation, while the command still owns its serialized workflow. The same-session case restores the active footer; a replaced/shut-down session receives no stale redraw. Tests also verify unchanged active bytes, draft removal, and released terminal listeners. The write, History, profile, and child-tool boundaries are unchanged.

## External handoff and release limits

Live-provider confirmation is optional and remains unverified. The responsible role is an authorized provider account owner; prerequisites are working Pi authentication and explicit permission to spend provider quota. Run a short configuration conversation and verify real-provider tool interoperability. Local deterministic provider tests do not establish that result. Stop after one clear external or entitlement failure rather than retrying automatically. Do not describe live-provider compatibility as verified until this check is performed.

The automated terminal smoke targets Linux PTYs. Other operating systems, physical terminal/IME behavior, and subjective visual usability are not established by that smoke; platform maintainers can run the same workflow on their target terminal. These external checks do not block completion of the coding plan, but their behavior must remain identified as unverified.

No package publication, version tag, visibility change, or release workflow dispatch is authorized. The deliverable is a reviewed pull request, not a release.
